# PIF Fix Descriptions — Generate Draft Description + AC

You are running an automated workflow. Follow every step in order. Do not stop for clarification.

## Configuration

- **cloudId**: `CLOUD_ID_PLACEHOLDER`
- **project**: `PROJECT_PLACEHOLDER`
- **spaceId**: `SPACE_ID_PLACEHOLDER`
- **parentId**: `COMMAND_PAGE_PARENT_ID_PLACEHOLDER`
- **acField**: `AC_FIELD_PLACEHOLDER`
- **today**: `TODAY_PLACEHOLDER`

---

## Step 1 — Read ticket keys from execution plan

Read `state/execution_plan.json` using the Read tool.

Extract `config.fix_descriptions_keys` — a comma-separated string of Jira ticket keys (e.g., `"DCPFS-12345, DCPFS-67890"`).

Split by comma, strip whitespace from each key. Store as `TICKET_KEYS` list.

If the file doesn't exist or `fix_descriptions_keys` is empty:
```
Print: ℹ️  No ticket keys specified.
       To use fix_descriptions, go to the PIF Automation Commands page in Confluence,
       fill in "Fix descriptions — ticket keys" with DCPFS-XXXXX keys (comma-separated),
       check the fix_descriptions box, and re-run ./run_command.sh
```
Then stop.

Print: `→ [1/4] Ticket keys to process: {comma-separated list}`

---

## Step 2 — Fetch each ticket in detail

For each key in `TICKET_KEYS`, call `searchJiraIssuesUsingJql`:
```
JQL: key in ({comma-joined TICKET_KEYS})
fields: ["summary", "description", "status", "assignee", "parent", "comment", "AC_FIELD_PLACEHOLDER", "labels", "priority", "issuetype"]
maxResults: 50
responseContentFormat: markdown
```

For each ticket, collect:
- `key`, `summary`, `status.name`, `assignee.displayName`
- `parent.fields.summary` (epic name, for context)
- `description` (current description, may be null)
- `AC_FIELD_PLACEHOLDER` (current AC, may be null)
- ALL comments: `comment.comments[]` → `author.displayName`, `created`, `body` (first 300 chars each)
- `labels`, `priority.name`

Print: `→ [2/4] Fetched {count} tickets`

---

## Step 3 — Generate drafts for each ticket

For each ticket, using ALL available context (summary, epic, current description if any, comments, labels, priority):

**Draft description** (3-5 sentences, PM-style):
- What is this ticket about? (based on summary and epic)
- Who benefits or what problem does it solve?
- What is the expected outcome or deliverable?
- Include any technical context derived from comments (e.g., specific systems, APIs, services mentioned)
- Do NOT copy the summary verbatim as the first sentence

**Draft acceptance criteria** (4-6 bullet points, testable and specific):
- Use "The system should..." or "Given [context], when [action], then [outcome]" phrasing
- Cover the happy path (main success scenario)
- Cover at least 1 edge case or error condition
- Reference specific values, thresholds, or behaviors mentioned in comments when present
- Each bullet should be independently verifiable

If the ticket already has a non-trivial description (>50 chars), keep it and only draft the AC. Note this in the output.
If the ticket already has AC, keep it and only draft a description. Note this in the output.
